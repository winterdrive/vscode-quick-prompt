# 逆向工程筆記：Windsurf (Codeium Cascade)

## 1. 偵查過程 (Discovery)

Windsurf 使用 Codeium 的 Cascade 引擎。不同於其他 IDE 使用 JSON 或 SQLite，Windsurf 將對話狀態存放在 Protobuf (`.pb`) 檔案中。

## 2. 關鍵路徑

- **核心路徑**：`~/.codeium/windsurf/cascade/`
- **對話檔案**：`{uuid}.pb`

## 3. 資料格式

**Google Protobuf (二進位)**。

- 檔案頭部包含大量的二進位後設資料。
- 對話文本以長度預置 (Length-prefixed) 的方式嵌入。
- 檔案內容經過壓縮或特定編碼，使得傳統的 `strings` 命令會抓到大量雜訊 (如 `NFT0m#k...`)。

## 4. 提取策略 (二進位萃取)

由於 POC 階段不希望引入沉重的 Protobuf 編譯相依套件，我們採用了「二進位字串萃取」策略：

1. **區塊讀取**：讀取整個 `.pb` 檔案。
2. **啟發式掃描**：
   - 尋找連續長度 > 30 的位元組序列。
   - 該序列必須符合 UTF-8 編碼。
   - 檢查「語言密度」：字串中可列印字元 (含中文、英文、標點) 的比例須 > 85%。
   - 排除重複位元組 (如連續的 `0xFF` 或 `0x00`)。
3. **角色分配**：預設為 `assistant`角色，因為目前無法從二進位標籤中穩定區分 User/Assistant。

## 5. 目前瓶頸

- **格式封閉**：Protobuf 在沒有 `.proto` 定義的情況下極難完美解析。
- **雜訊問題**：部分二進位資料塊可能剛好符合 UTF-8 規則，導致提取出垃圾字串。
- **保底建議**：若此方法不穩定，應改為引導使用者手動複製。
